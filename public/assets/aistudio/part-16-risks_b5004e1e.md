### 16.2 Explicit Analysis Gaps & Unrecoverable Artifacts

In strict compliance with reverse-engineering integrity standards, the following 5 system elements are definitively classified as unrecoverable from the client APK artifact:

1. **Dart Source Code AST and Comments:** `libapp.so` contains compiled ARM64 machine code generated by the Flutter AOT compiler. High-level Dart classes, inline documentation, and source code comments cannot be reconstituted from the binary.
2. **55 Decompilation Failure Targets:** `jadx.log` documents exactly 55 methods where decompilation failed with "Method not decompiled" due to complex bytecode jump instructions and synthetic lambda wrappers. These methods require smali-level inspection during rebuild.
3. **Internal Cloud Infrastructure & Database Schemas:** Cloud ingest endpoints (NebulaLive, Transsion AI Gateway) are observable solely through client-side HTTP request and response structures. Server-side database tables, microservice topology, and distributed caches remain unobservable.
4. **Production Cryptographic Signing Keys:** The private release keystore used to sign `base.apk` (SHA-256 certificate fingerprint) and private OAuth client secrets are proprietary to Transsion release engineering and are not present in decompiled sources.
5. **Proprietary Vendor C++ Source Code:** Pre-compiled native libraries (`libnativelib.so`, `libsfwatchface.so`, `libRtkAesJni.so`) contain stripped C/C++ machine code. Internal algorithm implementations (e.g. proprietary calorie smoothing) must be treated as black-box binaries or replaced with standard open-source equivalents.
